- **Gejala (laporan user + screenshot):** klik tool teks lalu klik di kanvas untuk menempatkan teks — kotak edit teks selalu muncul di bagian bawah layar, bukan di titik klik; teks tidak bisa ditempatkan sesuai keinginan user. - **Temuan kunci (Playwright, sebelum fix — 1/7 lolos):** objek teksnya sendiri SELALU terbuat di posisi dokumen yang benar (Position X/Y cocok dengan titik klik; delta 2 klik = delta klik / zoom, persis). Yang meleset adalah **kotak edit teks (TextEditOverlay)**: offset konstan (+16, −114) px pada zoom 82%, membesar bersama zoom/pan (sampai +191, +373 pada zoom 313% + pan). Bukti bedah: overlay `left/top` = 368/259,76 px padahal yang benar 352/373,76 px (klik 652,400; panRef (24,154) dari matriks viewport; zoom 0,82) — persis cocok dengan `pan` = (40,40) = nilai awal `initP`, bukan panRef.
- **Root cause:** `pan` (React state) vs `panRef` (nilai hidup yang dipakai `toDoc`, transform viewport SVG, dan renderer CanvasKit) **tidak pernah disinkronkan dalam pemakaian normal**. Tiga-satunya pemanggilan `setPan` — di `flushView()`, `settleFn` di `softView()`, dan akhir drag-pan di `onPointerUp` — semuanya dibungkus gate `vcSimpRef.current || renamingId || renderCfg.debugMode !== 'none' || (sel/objek > 64)`. Di luar kondisi itu `setPan` tidak pernah jalan, jadi state pan tertinggal di `initP` seumur sesi sementara `panRef` bergerak bebas lewat fitView/zoom/pan. `setZoom` di tempat yang sama TIDAK bergate, jadi zoom state selalu benar — hanya pan yang basi. `TextEditOverlay` adalah satu-satunya konsumen state `pan` untuk penempatan (posisi = `pan + doc*zoom`), sehingga kotak editnya meleset sebesar `(initP − panRef)` — makin jauh saat user zoom/pan, dan ke bawah bila `panRef.y << pan.y` (kasus user).
- **Perbaikan (`VectorEditor.jsx`, 3 tempat, backup `.bak-placefix`):** gate dihapus — `setPan` kini selalu dipanggil saat view settle (flushView, settleFn) dan saat drag-pan selesai, sama seperti `setZoom` yang memang sudah tanpa syarat. Tidak menambah render baru (setPan ikut dalam render pass yang sama dengan setZoom). `TextEditOverlay` tetap memakai state `pan` (reaktif, mengikuti pan saat edit) — tidak diganti ke `panRef` agar overlay tetap mengikuti bila user menggeser kanvas saat sedang mengetik.
- **Verifikasi:** tes regresi baru di `tests/text-tool.test.cjs` (merah di kode lama — gate terdeteksi — hijau sesudah fix); `npm test` **76/76**; `npm run build:web` exit 0; Playwright 7/7 skenario lolos (tengah, kiri-atas, kanan-bawah, zoom 313%, setelah pan, drag-buat box, delta 2 klik) dengan offset overlay **tepat 0 px** di semua skenario (sebelumnya sampai +191/+373); replika kondisi user (Frame + objek, zoom 160%, pan besar `panRef=(-468, 139)`) — overlay tepat di titik klik, teks hasil commit "TeksDiSini" ter-render di titik klik, 0 pageerror/console error.
