# Text Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add editable text objects with SkParagraph rendering, basic typography controls, legacy text migration, and explicit editable path conversion through opentype.js.

**Architecture:** Keep text in `doc.objects` and render it in order through CanvasKit. Use a DOM textarea only while editing. Resolve each face to offline font bytes shared by CanvasKit and opentype.js. Extend project asset handling for imported fonts.

**Tech Stack:** React 18, CanvasKit 0.40 SkParagraph, opentype.js, IndexedDB, Node tests, Chrome/Edge smoke tests.

**Spec:** `docs/superpowers/specs/2026-11-12-text-tool-design.md`

## Global Constraints

- No runtime network fetch; `file://` and Tauri must work offline.
- Preserve legacy text content, baseline coordinates, and layer order.
- Missing or incompatible fonts must never silently become incorrect outlines.
- No HarfBuzz.js until CanvasKit shaping proves insufficient.
- No Git repository is present in this workspace; work in place and do not attempt commits.

## Review Focus

- Legacy text from older projects remains editable and survives save, undo, backup, and reopen.
- Imported font bytes survive project duplication and backup/restore.
- Text draw order and raster/SVG export match the editor, including multiline and alignment.
- Converting ligatures, diacritics, and missing glyphs either matches display or fails visibly.
- Large or invalid font files and long text do not freeze or corrupt the project.
